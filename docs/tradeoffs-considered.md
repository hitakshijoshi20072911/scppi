## Security vs Production Trade-offs

The following security controls **cannot be traded away** for performance, cost, complexity, or operational convenience:

- Authentication
- Authorisation
- Tenant isolation
- Secret protection
- Financial approval
- Invoice idempotency
- Webhook signature validation (when webhooks are added)
- Safe production migration
- Audit integrity

Where performance, cost, complexity and security conflict, assess the actual risk and record the decision in this document. The choice must explain what is being traded off, why the decision was necessary, the production benefit, the security impact, and the mitigation.

## Bootstrap Trade-offs

The following trade-offs were made during initial repository setup:

- **Documentation before implementation:** Full documentation system created before any feature implementation. Trade-off: slower initial progress. Benefit: clear guidance for implementation and AI agents. Mitigation: documentation is incremental and can be updated.

- **Minimal backend scaffold:** Only health endpoints and basic configuration implemented. Trade-off: no business logic yet. Benefit: proves foundation is buildable. Mitigation: business logic added incrementally per milestone.

- **Git repository before full implementation:** Repository initialised and pushed before all features implemented. Trade-off: early commit may require rebasing. Benefit: version control from start; easier collaboration. Mitigation: feature branches for milestones.
